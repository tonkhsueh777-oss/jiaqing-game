# 《嘉庆君游台湾：御前争霸》V2 Mac 本机端 2.5D 设计规格

日期：2026-09-03
状态：待用户最终确认后进入实现计划

## 1. 目标

在不破坏当前 V43 已稳定可玩的规则、AI、卡牌与胜负结构的前提下，制作第二版 V2 本机端演出版。

第一目标平台：Mac。

必须同时支持：
- Intel Mac
- Apple Silicon Mac（M 系列）

后续平台：Windows。V2 从第一天就采用平台无关的游戏核心和表现层，避免 Windows 版重写。

V2 的核心目标不是增加大量新规则，而是把“能玩”升级为“更像真正单机游戏、视觉冲击更强、操作反馈更清楚、特殊牌更有演出感”。

## 2. 不改动范围

以下内容作为 V43 稳定内核保留：
- 回合顺序
- 3 人单机局结构
- 抽牌 / 手牌上限 / 弃牌机制
- 地牌开放逻辑
- 巡游与明察逻辑
- 4 类宝物与胜利条件
- 计策牌现有规则
  - 恶霸王豹：跳过对手下一个完整回合
  - 火烧百顺楼：随机烧掉对手 1 张手牌，受害者下回合以剩余手牌开始，动作结束后再补至 3 张
  - 假绿菊花：与指定对手交换当前位置
- 王牌交换宝物逻辑
- AI 决策基本逻辑
- 当前存档语义

除非后续单独提出规则需求，否则 V2 不在表现层开发时修改上述规则。

## 3. 技术路线

### 3.1 推荐结构

采用：
- Tauri 作为桌面应用壳
- 现有 JavaScript 游戏规则逻辑作为核心
- PixiJS 作为 2.5D 主舞台与特效表现层
- HTML/CSS 作为信息 UI、行动说明、按钮、弹窗层
- WebAudio 作为音效系统

### 3.2 为什么这样做

此结构能最大限度复用现有网页版本，同时明显提升本机端表现。

PixiJS 只负责需要“游戏感”的部分：
- 主舞台
- 地牌场景
- 棋子
- 卡牌飞行
- 粒子
- 技能特效
- 宝物飞行动画

DOM UI 继续负责：
- 玩家信息
- 行动说明
- 可执行动作
- 牌面预览
- 弹窗
- 设置

这样可以降低旧 Mac 的负担，也便于未来 Windows 版本复用。

## 4. 项目隔离

现有网页版继续保持在当前根目录，不直接改造成桌面版。

新增独立 V2 目录，建议结构：

```text
/desktop-v2/
  /app/               桌面 UI 与入口
  /scene/             2.5D 主舞台
  /effects/           粒子、技能、镜头效果
  /audio/             音效控制
  /platform/          Mac / Windows 平台抽象
  /assets/            V2 美术资源
  /tests/             V2 集成测试
  /src-tauri/         Tauri 桌面壳
/shared-core/         从现有 V43 抽出的稳定规则核心
```

第一阶段不移动线上版本文件，先通过适配层调用现有 V43 内核；等 V2 跑通后再决定是否整理 shared-core。

## 5. Mac 窗口与显示策略

### 5.1 启动方式

默认：窗口模式启动。

提供：
- 一键全屏
- 一键退出全屏
- 窗口缩放
- 记住上一次窗口尺寸

### 5.2 设计基准

主视觉基准：1920×1080。

但不能要求用户必须有 1080p 屏幕。

实际布局必须适配：
- 1440×900
- 1680×1050
- 1920×1080
- 更高分辨率 Retina 显示器

布局采用逻辑坐标缩放，保证旧 Mac 上不出现控件被裁切。

## 6. 老 Mac 性能策略

V2 不做重型实时 3D。

采用轻量 2.5D：
- 分层 PNG / WebP 精灵
- 轻量粒子
- 少量模糊与发光
- CSS / GPU transform
- 局部 WebGL 场景
- H.264 技能视频继续复用

提供两个画质档：

### 标准模式
- 粒子正常
- 动态光正常
- 轻微镜头运动
- 地牌环境动画开启

### 低负载模式
- 粒子数量降低
- 模糊关闭或降低
- 镜头运动减少
- 环境动画降频

旧 Intel Mac 默认优先稳定帧率，而不是追求复杂光效。

## 7. V2 主界面布局

保留当前三栏信息逻辑，但视觉重新设计。

### 中央主舞台
- 最大视觉面积
- 御案 / 古地图式 2.5D 桌面
- 中央起点台座
- 四个地牌舞台
- 玩家棋子
- 移动路径
- 技能效果

### 底部手牌区
- 扇形或轻弧形排列
- 悬停抬升
- 点击选中
- 可用牌提示
- 抽牌与弃牌飞行动画

### 左侧信息区
- 玩家总览
- 宝物总览
- 牌堆状态
- 行动记录

信息框采用半透明深青绿 / 铜金框，不占主视觉。

### 右侧操作区
保留当前已经验证有效的交互层级：
- 牌面预览
- 行动说明
- 可执行动作
- 新游戏

“行动说明”继续作为新手与实时操作的核心提示区。

## 8. 2.5D 场景设计

### 8.1 主舞台
视觉关键词：
- 深青绿
- 暗金铜
- 古地图
- 御案
- 微缩桌游
- 半写实
- 历史国风

主舞台由 5 层组成：
1. 背景氛围层
2. 御案 / 桌面层
3. 地牌与建筑层
4. 棋子 / 卡牌交互层
5. 粒子 / 光效 / UI 提示层

### 8.2 四个地点
每张地牌做成“弹起式微缩场景”，保留卡牌身份但加入建筑纵深。

- 台南府城
- 麻豆古镇
- 鹿港
- 诸罗大营

地牌状态：
- 未开放：暗色卡座、轮廓光
- 开放：建筑弹起、场景亮起
- 当前玩家所在：台座光环
- 可移动目标：路径和落点呼吸光

## 9. 手牌系统

### 默认状态
3 张手牌在底部轻弧形展开。

### 悬停
- 卡牌向上抬升
- 放大约 8%～12%
- 投影增强
- 功能摘要出现

### 可用牌
- 金色柔光边缘

### 不可用牌
- 降低饱和度
- 保留可读性
- 点击后右侧说明为什么不可用

### 选中牌
- 向上抬升
- 金边锁定
- 右侧显示完整操作说明

## 10. 抽牌与弃牌

### 抽牌
流程：
1. 抽牌堆顶部轻微浮起
2. 卡牌翻转或滑出
3. 飞向手牌位置
4. 插入手牌并重新排布

### 弃牌
流程：
1. 被弃牌向前抬升
2. 飞向弃牌堆
3. 落下并加入轻微叠牌偏移

无牌可出时，弃牌堆与右侧行动说明同时出现呼吸提示。

## 11. 玩家棋子

三名玩家使用独立棋子：
- 玩家本人
- AI 玩家一
- AI 玩家二

不再只用“我 / 甲 / 乙”圆点。

棋子必须具备：
- 清楚的颜色区分
- 小型徽章 / 人物标识
- 当前回合光环
- 位移轨迹
- 被技能影响状态图标

## 12. 特殊牌演出

### 恶霸王豹
- 黑金豹影冲击
- 目标玩家被锁定
- 封印 / 锁链视觉
- 下一回合跳过时再次出现短提示

### 火烧百顺楼
- 火焰卷入目标手牌
- 随机 1 张牌被点燃
- 卡牌烧毁 / 飞灰
- 飞入弃牌堆
- 受害玩家状态提示“本回合少 1 张手牌”

### 假绿菊花
- 两个棋子脚下出现交换阵
- 光轨连接双方
- 双方沿弧线或交叉轨迹换位
- 交换完成后显示地点名称

### 嘉庆令
- 御令卷轴 / 金色圣旨展开
- 双方宝物被高亮
- 宝物沿路径对飞交换

### 王德禄令
- 军令牌 / 武将调令风格
- 比嘉庆令更有军阵与力量感
- 宝物交换逻辑一致，但表现风格不同

## 13. 宝物系统演出

4 件宝物：
- 金印
- 宝剑
- 火枪
- 柚子

获得宝物时：
1. 宝物大图短暂出现
2. 光效与音效
3. 飞入玩家宝物栏
4. 收集进度更新

当玩家拥有 3 种不同宝物时，宝物栏进入“临近胜利”状态，但不遮挡主界面。

## 14. 回合节奏

每个回合分为清楚的视觉阶段：

1. 当前玩家提示
2. 当前玩家棋子 / 面板高亮
3. 可行动牌显示
4. 玩家执行动作
5. 动作演出
6. 补牌
7. 短暂回合结束提示
8. 下一位玩家

AI 不能瞬间完成全部步骤，需要保留适度停顿，但总节奏不能拖慢。

## 15. 音效

第一版至少包含：
- UI 点击
- 卡牌悬停
- 抽牌
- 弃牌
- 地牌开放
- 玩家移动
- 获得宝物
- 回合切换
- 三张计策牌专属音效
- 两张王牌专属音效
- 胜利
- 失败

设置中提供：
- 总音量
- 音效音量
- 静音

背景音乐可以在 V2.1 再加入，V2.0 不强制。

## 16. 存档与平台抽象

建立平台无关接口：

```text
GameStorage.save()
GameStorage.load()
GameStorage.delete()
GameSettings.get()
GameSettings.set()
PlatformWindow.toggleFullscreen()
```

Mac 与 Windows 只在 platform 层处理路径、窗口与打包差异。

游戏规则不直接调用 macOS API。

## 17. Mac 打包目标

第一阶段输出：
- Universal `.app`
- Universal `.dmg`

开发阶段可先提供未签名测试包。

正式发布阶段再处理：
- Apple Developer ID 签名
- notarization
- Windows 后续签名

## 18. Windows 兼容预留

V2 禁止写死：
- macOS 文件路径
- Mac 专属快捷键逻辑
- Cocoa 专属窗口行为

快捷键通过映射层处理。

未来 Windows 版复用：
- 游戏规则
- 2.5D 场景
- UI
- 音效
- 资源
- 存档格式

只替换平台构建与少量平台接口。

## 19. 第一阶段实现范围：V2.0

V2.0 目标不是一次做完所有高级演出，而是先得到第一个“明显比网页版本像单机游戏”的 Mac 可运行版本。

必须完成：
1. Tauri Mac Universal 项目壳
2. V43 游戏规则接入
3. 主界面 2.5D 重新布局
4. 四地点卡 2.5D 舞台框架
5. 玩家棋子与移动动画
6. 手牌悬停 / 选中 / 抽牌 / 弃牌动画
7. 右侧行动说明接入
8. 宝物获得基础演出
9. 特殊牌继续使用现有 6 秒视频作为第一阶段技能演出
10. 基础音效
11. 胜利 / 失败结算重做
12. 窗口 / 全屏切换
13. Intel + Apple Silicon 打包验证
14. 低负载模式

## 20. V2.1 之后增强

V2.1：
- 三张计策牌改成原生 2.5D 技能特效
- 两张王牌改成原生 2.5D 技能特效
- 地牌轻微环境动画
- 宝物交换完整动画

V2.2：
- 更完整环境音
- 镜头推拉
- 更强胜负结算
- 更多场景动态

## 21. 测试要求

### 规则回归
所有 V43 现有规则测试继续通过。

### 新增桌面测试
- Mac 窗口启动
- 窗口缩放不裁切
- 全屏切换
- 存档重启后可恢复
- 特殊牌完整流程
- Intel 架构构建
- Apple Silicon 架构构建
- Universal 合并包构建

### 表现层验证
每个动作必须能从画面看懂结果：
- 谁行动
- 打了什么牌
- 目标是谁
- 位置是否变化
- 手牌是否减少
- 宝物是否获得 / 交换

## 22. V2.0 完成标准

满足以下条件才能称为第一版本机端完成：

- Mac Intel 可打开
- Apple Silicon 可打开
- 默认窗口模式正常
- 可切全屏
- 完整玩完一局无阻塞
- V43 所有核心规则仍正确
- 三张计策和两张王牌可正常使用
- 主要动作均有视觉反馈
- 旧 Mac 低负载模式可正常游玩
- 后续 Windows 不需要重写规则或 UI 架构

## 23. 视觉总方向

统一关键词：

> 清代台湾历史桌游、御前争霸、2.5D 微缩舞台、深青绿、暗金铜、古地图、御案、半写实、电影级局部光影、清晰可读、桌面单机游戏感、精致但不堆砌。

原则：
- 主舞台比 UI 更抢眼
- UI 信息始终清楚
- 特效服务于“让玩家看懂发生了什么”
- 旧 Mac 性能优先
- 不做重型 3D
