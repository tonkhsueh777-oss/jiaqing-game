# 《嘉庆君游台湾：御前争霸》macOS 2.5D 桌面版设计规格

日期：2026-09-01  
目标版本：Mac Desktop V1.0  
基础版本：现有 V30 网页版  
技术方向：Tauri 2 + 现有 HTML/CSS/JavaScript + CSS 3D + Canvas/WebGL 轻量特效

## 1. 目标

把现有 V30 从“网页纸牌游戏”升级为可离线安装、可全屏运行、具有明显空间层次与电影感演出的 macOS 单机游戏，同时保留现有游戏规则、AI、牌组、版面结构和交互逻辑。

桌面版的重点不是重做玩法，而是新增独立的 2.5D 表现层：

- 牌桌空间与景深
- 卡牌厚度、透视、悬浮、翻转
- 抽牌仪式动画
- 真人玩家宝物电影式出现演出
- AI 行动可视化，但 AI 获宝不播放真人宝物大演出
- 背景环境动态、粒子、光效、环境音与动作音效
- macOS 本地运行、离线资源、全屏窗口

## 2. 明确不改动的范围

V1.0 不修改以下内容：

- 游戏胜负条件
- 牌张数量与牌面规则
- AI 决策规则
- 玩家回合流程
- 四张地牌的基本布局关系
- 手牌上限与补牌规则
- 真人玩家与 AI 的宝物判定规则
- 现有网页版的手机响应式逻辑

所有桌面增强必须作为可开关的表现层存在，不允许视觉系统反向改变游戏状态。

## 3. 当前项目基础

现有入口 `index.html` 已按功能拆分加载多个模块，包含：

- `src/state.js`：牌局状态
- `src/rules.js`：游戏规则
- `src/ai.js`：AI 行为
- `src/storage.js`：本地存储
- `src/draw-ritual.js` 与 `src/v22-draw-ritual-ui.js`：搓牌 / 抽牌仪式
- `src/v23-visual-effects-logic.js` 与 `src/v23-visual-effects.js`：视觉事件与宝物表现
- `src/v30-beginner-assist-*`：V30 新手辅助

现有代码已经具备“真人宝物演出、AI 宝物静默”的逻辑边界，V1.0 应复用并加强这一机制，而不是另建一套重复判定。

## 4. 总体架构

桌面版保持现有游戏核心不动，在其外侧增加两个层：

```text
Tauri 2 Desktop Shell
│
├── Existing V30 Game Core
│   ├── state
│   ├── rules
│   ├── ai
│   ├── storage
│   └── existing UI
│
├── Desktop Presentation Layer
│   ├── desktop runtime detection
│   ├── 2.5D scene controller
│   ├── card motion controller
│   ├── draw/reveal choreography
│   ├── treasure cinematic controller
│   ├── AI action choreography
│   └── audio controller
│
└── Tauri Native Layer
    ├── application window
    ├── fullscreen
    ├── local packaged assets
    └── .app / .dmg packaging
```

网页与桌面共用同一个游戏核心。桌面表现通过 `body.desktop-mode` 或等价运行时标记启用，普通网页访问不加载重型桌面效果。

## 5. 2.5D 场景设计

桌面场景分为五个视觉深度层：

1. 宫廷 / 御书房背景
2. 桌面装饰与环境光
3. 中央牌桌与四张地牌
4. 玩家手牌、宝物、操作浮层
5. 粒子、烟雾、金尘、聚光等前景效果

鼠标移动只产生轻微视差，禁止大幅晃动：

- 背景：约 1% 位移
- 桌面：约 2% 位移
- 前景牌层：约 3% 位移

所有视差必须支持 `prefers-reduced-motion` 降级。

## 6. 卡牌 2.5D 交互

卡牌不使用真实物理模型，优先使用 CSS 3D transform：

- `perspective`
- `rotateX / rotateY`
- `translateZ`
- 动态阴影
- 边缘高光
- 悬停浮起
- 轻微回弹

目标效果：

- 鼠标经过卡牌时抬高约 8–12 px
- 最大倾角控制在约 3–5°
- 重要卡牌可以出现边缘呼吸光
- 离开后平滑复位

视觉反馈不得改变点击区域和现有选牌逻辑。

## 7. 抽牌与翻牌演出

复用现有 `draw-ritual.js` 的进度、揭牌阈值与倾斜逻辑，在桌面模式上增加镜头和空间表现。

标准流程：

1. 牌堆轻微反馈
2. 顶牌沿桌面向玩家方向滑出
3. 卡牌悬停于中央，显示牌背
4. 沿 Y 轴翻转揭牌
5. 普通牌飞入玩家手牌
6. 宝物牌转入宝物演出流程

目标时长约 2.5–3 秒。动画过程中必须防止重复输入造成重复抽牌。

## 8. 真人宝物电影演出

宝物演出是 V1.0 的核心视觉招牌。

触发条件继续使用现有 `shouldShowTreasureGain()` 逻辑：只允许 `human` 的宝物增量触发大演出。

演出流程：

1. 背景与牌桌压暗
2. 中央出现聚光和低频音效
3. 宝物主图从缩小状态升起
4. 宝物轻微左右旋转，不做无限旋转
5. 背后出现光环、金尘、薄烟与层次阴影
6. 显示宝物名称与一句简短说明
7. 宝物缩小并飞入玩家宝物栏
8. 恢复正常牌桌亮度

总时长建议 3–4 秒。

AI 获取宝物时只执行轻量反馈：宝物图标或光点飞入 AI 宝物栏，不压暗全屏、不暂停玩家视线、不播放完整宝物演出。

## 9. AI 行动可视化

AI 仍由现有 `ai.js` 决策。表现层只监听状态变化与动作日志：

- AI 区域轻亮表示开始行动
- 抽牌时显示卡牌从牌堆飞向 AI 区
- 出牌时卡牌从 AI 区飞向中央
- 目标地牌产生短暂高亮
- 行动结束后恢复普通状态

表现时长必须短于真人抽牌演出，避免 AI 回合拖沓。

## 10. 背景动态与氛围

V1.0 不使用高码率循环视频背景，优先采用轻量分层资源：

- 烛光或灯影缓动
- 香炉薄烟
- 微量空气尘埃
- 窗外树影或纸窗光影
- 桌面暖光呼吸

背景动态持续存在但强度必须低，不能抢夺牌面可读性。

## 11. 音频设计

音频系统分三层：

### 环境音

- 御书房 / 宫廷安静环境
- 极轻木屋、风声或室内空气感

### 操作音

- 卡牌悬停：极轻纸张摩擦
- 抽牌：纸牌抽离
- 翻牌：短促 whoosh
- 落牌：木桌轻响
- UI 操作：轻确认音

### 重要事件音

- 宝物出现：低频 + 金属/玉石质感提示
- 宝物入库：清脆确认
- 胜利：短完整音乐 Cue

音频必须允许总音量、音乐、音效分别关闭；设置保存在本地。

## 12. Tauri macOS 桌面层

V1.0 使用 Tauri 2 封装现有前端。

目标产物：

- `.app`
- `.dmg`
- 优先支持 Apple Silicon 与 Intel 的 Universal 构建

窗口要求：

- 默认使用宽屏桌面尺寸
- 支持最大化
- 支持全屏
- 禁止导航到外部页面
- 所有运行资源包含在安装包内
- 断网后游戏仍可完整运行

V1.0 不依赖在线 CDN、在线字体、在线音效或远程脚本。

## 13. 新增文件建议

桌面表现层建议新增独立文件，不把 V30 逻辑继续堆进旧文件：

```text
src/desktop-runtime.js

src/desktop-card-motion.js
src/desktop-draw-cinematic.js
src/desktop-treasure-cinematic.js
src/desktop-ai-cinematic.js
```

如需粒子系统，优先建立单一 `canvas` 特效层；只有后续确认某些宝物必须使用真实 3D 模型时，才引入少量本地 Three.js，避免 V1.0 过度增重。

## 14. 事件与数据流

原则：游戏状态是唯一真源，视觉层不可直接改规则状态。

```text
Player / AI action
      ↓
Existing rules / state
      ↓
State change + log
      ↓
Presentation event mapper
      ↓
2.5D animation / audio
```

宝物事件继续通过“前后状态快照差异”识别；抽牌演出通过现有 DrawRitual 逻辑控制揭牌时机。

任何动画失败都必须允许游戏状态继续，不允许因为视觉层报错导致牌局卡死。

## 15. 性能预算

目标是“轻量桌面游戏”，而不是重型 3D：

- 桌面游戏过程中目标 60 fps
- 允许低性能设备自动减少粒子数量
- 单个持续 Canvas 特效层
- 不使用多个全屏 WebGL context
- 背景图片优先 WebP / PNG
- 动画尽量使用 transform / opacity
- 阴影与 blur 控制数量
- 大型粒子只在宝物与胜利演出期间出现

若帧率明显下降，应先降级粒子和 blur，而不是降低牌面清晰度。

## 16. 降级策略

桌面效果必须可退化：

- `prefers-reduced-motion`：关闭视差、减少翻转和镜头移动
- Canvas/WebGL 不可用：保留 CSS 3D 和基本淡入淡出
- 音频初始化失败：继续游戏，不阻塞 UI
- 桌面检测失败：回到当前网页版视觉表现

## 17. 测试策略

继续沿用项目现有 Node `node:test` 风格，对纯逻辑进行单元测试。

重点测试：

- 桌面运行时判定
- 真人宝物才触发完整演出
- AI 宝物不触发完整演出
- 演出队列防重复
- 抽牌演出期间重复输入被拦截
- 动画结束后交互状态恢复
- 关闭特效时规则结果完全一致

人工验收：

- 断网启动
- `.app` 直接启动
- `.dmg` 安装
- 最大化 / 全屏
- 连续多局无卡死
- 宝物演出完成后可以继续操作
- AI 回合不会过慢
- 网页版 V30 行为不受影响

## 18. V1.0 交付范围

必须完成：

1. Tauri macOS 单机外壳
2. 桌面运行模式检测
3. 2.5D 牌桌空间与轻视差
4. 卡牌悬停 / 厚度 / 透视
5. 抽牌与翻牌电影式演出
6. 真人宝物完整演出
7. AI 行动轻量演出
8. 背景环境动态
9. 桌面音频控制
10. `.app` 与 `.dmg` 构建流程

暂不进入 V1.0：

- 真 3D 人物
- 真实物理引擎
- 可自由旋转的 3D 牌桌
- 大型 3D 场景
- 联机
- 剧情模式
- 大量 3D 宝物模型

## 19. 验收标准

V1.0 被视为完成，必须同时满足：

- 规则结果与 V30 一致
- 网页版仍可正常使用
- Mac 版可断网游玩
- 玩家抽牌有完整 2.5D 抽牌 / 翻牌演出
- 真人取得宝物出现完整电影演出
- AI 取得宝物不出现完整宝物演出
- 卡牌具有稳定的伪 3D 悬停和空间感
- 牌桌背景有低强度动态环境
- 游戏在正常桌面尺寸下保持流畅
- 可构建 `.app` 与 `.dmg`

## 20. 后续版本方向

V1.1 可加入：

- 启动页与主菜单
- 自动存档 / 继续游戏
- 宝物图鉴
- 胜利结算动画强化
- 更多场景主题

V2.0 再评估：

- 少量真实 3D 宝物模型
- Three.js 特殊展示场景
- 更复杂镜头运动
- 角色立绘或角色反应动画

此规格以“视觉明显升级、玩法零破坏、桌面轻量化”为最高优先级。
