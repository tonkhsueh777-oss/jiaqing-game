# V31 匿名游玩统计与评价系统设计

## 目标
在不要求玩家注册、不填写姓名、电话或邮箱的前提下，为《嘉庆君游台湾：御前争霸》增加轻量匿名统计与评价功能。

玩家端需要做到：
- 每次打开网页自动记一次体验访问。
- 公开显示今日体验次数、累计体验次数、点赞数、需要改进数。
- 玩家可点击“👍 好玩”或“👎 需要改进”。
- 点击“👎 需要改进”后弹出快速原因选单。
- 反馈全匿名，不公开个人文字内容。

管理端需要做到：
- 查看今日访问、累计访问、开局次数、完成局数。
- 查看点赞数、需要改进数。
- 查看各类改进原因的数量。

## 技术方案
继续使用 GitHub Pages 作为游戏前端，接入一个极简 Supabase 数据端。Supabase 只负责保存匿名事件和评价汇总，不承载游戏本身。

选择 Supabase 的原因：
- GitHub Pages 本身不能保存跨玩家共享数据。
- 不需要玩家登录。
- 前端可以直接提交匿名事件。
- 数据表结构简单，后续容易查看和导出。
- 不需要额外开发复杂管理员后台，项目维护成本低。

## 前台交互
在现有资讯区底部增加“玩家反馈”模块，不改变棋盘、手牌和规则区布局。

公开显示：
- 今日体验：N
- 累计体验：N
- 👍 好玩：N
- 👎 需要改进：N

按钮行为：
1. 点击“👍 好玩”后直接提交点赞，显示“感谢反馈”。
2. 点击“👎 需要改进”后打开轻量弹窗，提供：
   - 规则不容易懂
   - 操作不顺
   - 手机版问题
   - 游戏节奏
   - 画面 / 音效
   - 其他
3. 玩家选择一个原因即可提交。
4. 可选提供简短补充意见输入框，但不强制填写。

## 统计事件
记录以下匿名事件：
- `visit`：每次打开网页记 1 次。
- `game_start`：玩家开始新游戏时记 1 次。
- `game_complete`：出现胜者并完成一局时记 1 次。
- `like`：点击“好玩”。
- `dislike`：点击“需要改进”。

不做设备去重；同一个人多次进入可重复计数，符合本项目“简单统计即可”的目标。

## 数据结构
使用两张表即可：

### `game_events`
- `id`
- `event_type`
- `created_at`

### `game_feedback`
- `id`
- `rating`：`like` / `dislike`
- `reason`：差评原因，可为空
- `comment`：可选短文字，可为空
- `created_at`

不保存姓名、电话、邮箱、账号或其他身份资料。

## 前台读取方式
前台读取聚合统计结果，而不是完整反馈记录。

显示：
- 今日 `visit` 数量
- 累计 `visit` 数量
- 累计 `like` 数量
- 累计 `dislike` 数量

详细的差评原因只在数据后台查看，不在玩家之间公开。

## 安全与限制
- 只允许匿名新增事件和反馈。
- 玩家端不提供删除或修改其他数据的能力。
- 公开接口只返回计数汇总，不返回完整反馈内容。
- 不追求严格防刷；本功能用于体验统计和产品改进，不作为财务或正式审计数据。
- 数据端不可用时，游戏本身仍正常运行；统计模块显示“暂时无法载入”，不能阻断游戏。

## 与现有游戏的隔离
V31 只新增统计与评价层：
- 不修改游戏规则。
- 不修改 AI 行为。
- 不修改牌堆数量和抽牌逻辑。
- 不修改胜负条件。
- 不修改桌面/手机版棋盘拓扑。
- 不修改卡牌原图。

## 测试要求
- 页面打开时只发送一次 `visit` 事件。
- 新游戏开始时发送 `game_start`。
- 一局真正结束时只发送一次 `game_complete`。
- 点赞与差评按钮均可正常提交。
- 差评原因弹窗可在手机和电脑端操作。
- Supabase 无法连接时不影响游戏核心功能。
- 公开统计数字刷新后可正确更新。
